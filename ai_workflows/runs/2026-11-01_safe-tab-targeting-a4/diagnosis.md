| # | Finding | Evidence |
|---|---|---|
| D1 | **False "the tab is still open" (N-PC4, seen on the PC 2026-11-01).** The check after `control_browser close` looks for the closed tab's id (right), but reads the tab list once, straight after `/json/close`, which only starts the close. `browser_tab close` waits up to 2 s for the id to go; `control_browser` does not. | `core/verifiers.ts:186-193`; `control/browserAgent.ts:478-485`; PC log: `Reopen closed tab: …results?search_query=…` then `✗ control_browser reported success, but the tab is still open`, and the next `browser_state` showed only `https://www.youtube.com/` |
| D2 | **Two tab finders with different rules (TRA-11).** `browserController.findTab`: a tab id, else the first tab whose title **or** URL contains the words. `browserState.findTab`: an empty name → the visible tab or the **first listed**; else id, title, then URL. Neither asks when several tabs match. | `control/browserController.ts:81-97`; `perception/browserState.ts:82-92` |
| D3 | **An empty name matches every tab (TRA-01).** `control_browser close` with no target calls `findTab('')`; `''` is inside every title, so the first listed tab closes, at level 1 (the risk engine treats an empty target like a blank tab). | `control/browserController.ts:89-92, 132-134`; `security/riskEngine.ts:227-228` |
| D4 | **Several matches → the first one, no question (TRA-01).** With two YouTube tabs, "close youtube tab" closes whichever Chrome lists first (usually the last used), not necessarily the one on screen. | same lines; PC 2026-11-01: the search tab closed, the home tab stayed |
| D5 | **No visible tab → the first listed tab (TRA-02).** When Chrome is minimised, "the current tab" becomes `tabs[0]`. | `perception/browserState.ts:77, 87` |
| D6 | **Key-press fallbacks into any browser in front (A2 review R2).** When JARVIS's Chrome does not answer, `closeActiveTab` presses Ctrl+W and `refreshTab` presses Ctrl+R if any browser window (Chrome, Edge, Firefox, …) is in front: that can be the owner's everyday Chrome. | `control/browserController.ts:170-175, 247-251` |
| D7 | **Port can be a stale file or 9222 (A2 review R2).** `cdpPort()` uses `JARVIS_CDP_PORT`, else the port in JARVIS's profile `DevToolsActivePort` file, else 9222. The file can outlive Chrome; 9222 can be another Chrome started with debugging. The read and tab tools use this port without checking it is JARVIS's Chrome; `jarvisChrome.running()` does check. | `perception/cdpClient.ts:24-28`; `perception/chromeProfile.ts:38-46`; `control/jarvisChrome.ts` |
| D8 | **Two permission rules for one action (N-PC6, TRA-12).** `control_browser close` of a YouTube, blank or empty target is level 1; `browser_tab close` of the same tab is level 2 (full control). On the PC the fast route closed YouTube without full control; the planner's `browser_tab close` was refused. | `security/riskEngine.ts:226-229`; `core/toolCatalog.ts:66, 408` |
| D9 | **Each "open youtube" adds a tab (N-PC5).** `showInJarvisChrome(url)` always opens a new tab, even when that site is already open in JARVIS's Chrome. | `control/jarvisChrome.ts:265-274` |
| D10 | **Closing the last tab closes JARVIS's Chrome (N-PC8, PC 2026-11-01).** Chrome exits when its last tab closes; nothing guards it, and the next tab request finds no Chrome ("JARVIS's own Chrome is not running"). | PC log: second "close the youtube tab", then `browser_state` failed 3 times |
| D11 | **"close this tab" / "close the tab" have no route (A3 follow-up).** Only "close current tab" does, and it reaches the Ctrl+W fallback (D6). | `core/deterministicRoutes.ts:230-231`; `core/orchestrator.ts:679-684` |
